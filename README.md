# SillyTavern 回复统计

一个轻量、独立的 SillyTavern 前端扩展，在每条 AI 回复的角色名旁显示：

`≈入12k · 出860 · 流32t/s · 思8.0s · 总30.0s`

- `入`：本轮输入 token 估算值。
- `出`：本轮输出 token 估算值。
- `流`：输出量除以请求总耗时得到的平均速度，包含排队和首字等待，不是严格的正文流式速度。
- 流速超过 `80 t/s` 时，仅流速数字显示红色；等于或低于 `80 t/s` 时保持原色。
- `思`：从与“流”相同的生成起点，到完整正文开始标签到达的可观测耗时。默认识别 `<content>`、`<context>`（大小写不敏感），可在输入框旁的魔法棒菜单打开“思考链时间”修改。
- `总`：从与“流”相同的生成起点，到整条回复生成结束的总耗时。
- `≈`：表示统计值为估算；`—`：表示旧消息或当前数据不足，不会伪装成 0。

`思` 在完整标签到达时立即停止，不再计入正文阶段；它是标签前耗时，不代表模型隐藏的内部推理时间。没有标签、非流式回复或旧消息会显示 `思 —`，不会把整段生成时间当成思考时间。

自定义标签默认以空格分隔；旧的中英文逗号和 `<content>` 写法仍兼容。弹窗中的“正文显示统计”只控制显示，不会删除已记录的数据。

扩展只监听 SillyTavern 原生消息事件，并读取当前消息和 itemized prompt 数据。它不会覆盖 `fetch`/XHR，不会修改请求、API 地址、密钥或预设，也不依赖 PayGo。

扩展只把少量数字写入 `message.extra.reply_token_stats`，不会保存完整提示词。

## 安装

将整个 `st-reply-stats` 文件夹复制到：

```text
SillyTavern/public/scripts/extensions/third-party/st-reply-stats
```

然后由用户自行刷新 SillyTavern 页面。通常不需要重启服务。

### Android / Termux

假设 SillyTavern 位于 `~/SillyTavern`，扩展文件夹已放进手机下载目录：

```sh
termux-setup-storage  # 仅首次需要
cp -r ~/storage/shared/Download/st-reply-stats \
  ~/SillyTavern/public/scripts/extensions/third-party/
```

如实际路径不同，请相应修改。电脑端完成项目并不代表手机端已经安装。

## v0.2.8：超速自动重生（可选）

魔棒 → 思考链时间 → 勾选「超过 80 自动删除并重生」。默认关闭，更新不会突然消耗 API。
沿用当前「流」统计口径，回复完成后严格大于 80 才触发，不用流式中途的瞬时值。
每轮自动重试次数默认 3 次，可在同一弹窗填写任意正整数（不含最初生成）。每次完成仍超过 80 就继续，直到速率不超过 80 或达到所设次数；达到上限后只标红。开关默认关闭，用户自行开启。仅单人聊天新回复/重生/swipe，续写、群聊、历史消息不自动处理。

触发前完整备份末条消息（含原有 swipes），写入并读回核验本浏览器 localStorage 后，才调用酒馆原生「重新生成」，真实替换末条回复。存储满、备份失败、切聊天、停止、编辑或已有新消息时不删除。所有旧备份保留，不轮换覆盖。

误删恢复：在原聊天的同一魔棒弹窗，勾选「恢复上次自动删除的回复」并保存。仅在尚未继续聊天时允许恢复，以免覆盖后续消息；恢复前也保留被替换回复。备份限当前浏览器/站点，不随聊天同步，清理站点数据会删除备份。不要把它当跨设备备份。

修复：允许酒馆收尾补写 swipe 元数据，避免误当用户编辑而取消；直接使用原生 Generate("regenerate")（与 ST-QuickBar 的重生入口相同），不再模拟点击菜单，也不依赖停止按钮 CSS 判断忙碌。原生收尾短暂忙碌时等待，停止/切聊天仍立即取消。
