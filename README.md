# SillyTavern 回复统计

一个轻量、独立的 SillyTavern 前端扩展，在每条 AI 回复的角色名旁显示：

`≈入12k · 出860 · 流32t/s · 思8.0s · 总30.0s`

- `入`：本轮输入 token 估算值。
- `出`：本轮输出 token 估算值。
- `流`：输出量除以请求总耗时得到的平均速度，包含排队和首字等待，不是严格的正文流式速度。
- 流速超过 `80 t/s` 时，仅流速数字显示红色；等于或低于 `80 t/s` 时保持原色。
- `思`：从与“流”相同的生成起点，到完整正文开始标签到达的可观测耗时。默认识别 `<content>`、`<context>`（大小写不敏感），可在输入框旁的魔法棒菜单打开“思考链时间”修改。
- `总`：从与“流”相同的生成起点，到整条回复生成结束的总耗时。
- `≈`：表示统计值为估算；`—`：表示旧消息或当前数据不足，不会伪装成 0。

`思` 在完整标签到达时立即停止，不再计入正文阶段；它是标签前耗时，不代表模型隐藏的内部推理时间。没有标签、非流式回复或旧消息会显示 `思 —`，不会把整段生成时间当成思考时间。

自定义标签默认以空格分隔；旧的中英文逗号和 `<content>` 写法仍兼容。弹窗中的“正文显示统计”只控制显示，不会删除已记录的数据。

扩展只监听 SillyTavern 原生消息事件，并读取当前消息和 itemized prompt 数据。它不会覆盖 `fetch`/XHR，不会修改请求、API 地址、密钥或预设，也不依赖 PayGo。

扩展只把少量数字写入 `message.extra.reply_token_stats`，不会保存完整提示词。

## 安装

将整个 `st-reply-stats` 文件夹复制到：

```text
SillyTavern/public/scripts/extensions/third-party/st-reply-stats
```

然后由用户自行刷新 SillyTavern 页面。通常不需要重启服务。

### Android / Termux

假设 SillyTavern 位于 `~/SillyTavern`，扩展文件夹已放进手机下载目录：

```sh
termux-setup-storage  # 仅首次需要
cp -r ~/storage/shared/Download/st-reply-stats \
  ~/SillyTavern/public/scripts/extensions/third-party/
```

如实际路径不同，请相应修改。电脑端完成项目并不代表手机端已经安装。

npm test

## v0.2.10：超速自动重生（可选）

魔棒 → 思考链时间 → 勾选「超过 80 自动删除并重生」。默认关闭，更新不会突然消耗 API。
沿用当前「流」统计口径，回复完成后严格大于 80 才触发，不用流式中途的瞬时值。
每轮自动重试次数默认 3 次，可在同一弹窗填写任意正整数（不含最初生成）。每次完成仍超过 80 就继续，直到速率不超过 80 或达到所设次数；达到上限后只标红。开关默认关闭，用户自行开启。仅单人聊天新回复/重生/swipe，续写、群聊、历史消息不自动处理。

触发前完整备份末条消息（含原有 swipes），写入并读回核验本浏览器 localStorage 后，才调用酒馆原生「重新生成」，真实替换末条回复。存储满、备份失败、切聊天、停止、编辑或已有新消息时不删除。所有旧备份保留，不轮换覆盖。

误删恢复：在原聊天的同一魔棒弹窗，勾选「恢复上次自动删除的回复」并保存。仅在尚未继续聊天时允许恢复，以免覆盖后续消息；恢复前也保留被替换回复。备份限当前浏览器/站点，不随聊天同步，清理站点数据会删除备份。不要把它当跨设备备份。

修复：允许酒馆收尾补写 swipe 元数据，避免误当用户编辑而取消；直接使用原生 Generate("regenerate")（与 ST-QuickBar 的重生入口相同），不再模拟点击菜单，也不依赖停止按钮 CSS 判断忙碌。原生收尾短暂忙碌时等待，停止/切聊天仍立即取消。

v0.2.9 安全修复：统计监听器不再被酒馆生成流程等待，统计异常/分词超时不能阻断正常发送；流式自动重生必须等旧 streamingProcessor 清空后才开始，避免旧请求收尾破坏新请求。保留默认 3 次及用户开关；尚未进行用户手机真机验证。

v0.2.10：消息完成后主动检查真正空闲状态，不依赖受主题影响的 GENERATION_ENDED；后台 quiet/dryRun 不再清除主生成跟踪；JSON 备份不依赖 HTTPS 专有 structuredClone。设置弹窗显示最近一次触发状态，便于定位未执行原因。

## v0.2.11：可见进度与失败恢复
每次自动重生之前先显示非阻塞提示，例如「第 1 条回复已生成，但速率超过 80，正在生成第 2 条回复」。默认 3 次重试最多生成到第 4 条，不会无限重试。
只有非空、带有效生成时间且流式处理成功结束的回复可触发。停止、报错、超时留下的未完成流式回复不会按超速自动删除。
原生重新生成报错或返回空白时，在仍是原聊天、原位置且没有新操作的前提下自动恢复旧回复并停止重试；已有部分新文字则保留，原回复仍可从备份恢复。失败结果会明确提示。插件不取消普通请求、不自行给 API 设置超时，也不会用弹窗等待确认阻塞生成。
验证范围：Node 隔离回归测试覆盖事件监听不阻塞、原生式先删除后失败、空白恢复、保留部分内容、切聊天和新操作保护；未在用户手机及真实模型 API 上验证。用户报告的约十分钟超时原因仍未确认，不能据此认定是速率问题。

## v0.2.12：避免更新后的混合模块缓存
插件入口、统计模块和重试模块的 URL 带同一版本号，避免浏览器将新版入口与旧版依赖混用。v0.2.11 新增模块导出时，旧依赖缓存会导致 ES 模块链接失败，整个统计栏不加载，酒馆自己的时间仍可能显示。
新增真实 ES 模块缓存 + jsdom DOM 回归：重现旧依赖导致初始化失败，验证版本化导入后输入/输出 token、流速和总时间均显示，自动重生关闭时仍计数且不调用生成。
这修复了一个可复现加载缺陷，但未读取用户手机日志，不能认定手机现场唯一原因就是缓存。更新后完整刷新页面；不要清理站点数据，以免丢失本地回复备份。
开发测试先执行 npm ci，再 npm test；jsdom 仅供测试，酒馆加载插件不需要安装 Node 依赖。

## v0.2.13：可设置输出 token 下限
同一个自动重生开关检查两个条件：最终流速 >80，或最终输出 token 低于你填写的阈值。魔棒设置新增「输出少于多少 token 时重生」，默认 3000，可保存自定义非负整数；填 0 只关闭短输出条件，超速条件仍有效。旧设置自动补上默认值，原来已开启的开关会应用新增条件。
满足任一个即重生；两者同时满足只重生一次，提示会同时列出原因和实际阈值。等于阈值不触发。使用统计栏既有「出」的 token 口径，可能包含模型思考，不是字数。
仅完整有效回复参与检查。输出未知、无效不是 0；输出有效但流速未知时，仍可按输出不足触发。共用原来的每轮重试次数（默认 3 次，不含首条），备份、失败恢复、停止/切聊天保护及默认关闭保持不变。

## v0.2.14：兼容旧版酒馆的输入统计来源
已确认官方 SillyTavern 1.13.0 及 1.12.14 没有 scripts/itemized-prompts.js。此前把它作为必需静态依赖，会令整个插件加载失败，而不仅是输入 token 缺失。
现在输入统计来源改为可选异步加载：新模块不可用时退回旧版 script.js 导出；两者都不可用或加载挂起，也不阻止输出、流速、时间和菜单初始化。输入未知显示 —，不会伪造数字。保留旧版导出的活绑定，切换聊天时不继续使用旧数组。
魔棒 → 思考链时间 的设置标题下可查看「统计显示：开/关；输入统计来源：可用/加载中/不可用」，不包含聊天内容。更新后完整刷新，标题应为 v0.2.14。
验证包括真实独立酒馆 HTTP 路由和 MIME、ES 模块及 jsdom 回归；本地 Chromium 因 socket EPERM 无法启动，未完成真实浏览器或手机布局验收，未访问用户酒馆、未调用真实模型 API。兼容缺陷已确认，但用户现场是否正是这个原因仍待验证。

## v0.2.15（候选，未发布）：失败片段、状态与上限保护
自动重生只有收到与本次尝试绑定的原生完整完成证据，才确认为成功；不再把 Promise 正常返回加非空片段当作成功。断流片段先备份，再在原聊天/原位置/未编辑条件下恢复原回复，停止重试链。手动停止也可恢复仍属于本次尝试的片段；后续编辑、发送、切聊天不会被覆盖。恢复按钮优先取原始回复，不误选失败片段。
重试状态随备份记录，刷新后可在设置页查看；输入框附近仅显示实际重试或结果状态，不显示普通统计跟踪噪声。原生生成过程中仍使用酒馆自身的重生流程，等待期间可能显示空候选；本版不宣称改成先生成后替换。
旧酒馆遗留的已停止/已中止 streamingProcessor 不再卡住恢复，后续非流式回复也不会被该旧指针误判失败；正常完成但尚未清理的指针仍等待收尾。
若本轮聊天补全请求明确给出 max_tokens/max_completion_tokens，且上限低于用户短输出阈值，仅跳过短输出重试（>80 超速条件仍独立生效）。未知上限不猜测。阈值默认 3000、每轮重试默认 3 次、可选开关保持。
这些改动不能证明用户现场首次请求超时的根因已解决。候选尚待隔离真实酒馆验证，不访问用户聊天或真实模型 API。
恢复时仅通过原生 addOneMessage(forceId) 重建末条目标消息，并移除同 ID 的旧 DOM；不使用旧版会追加整聊的 printMessages，也不 clearChat，避免复制整段聊天或重置提示词记录。
仅本插件发起的、确认归属的活动流式重试，连续 90 秒无新流事件时请求原生停止；思考流事件同样重置计时。首条正常生成、手动生成、非流式或无法确认归属的请求不会被自动停止。停止后仍等待原生结算再安全恢复；若未结算，只显示状态并保留备份，不覆盖仍在生成的内容。新生成、编辑、切聊天或其他后台请求会取消该尝试的停止权限。不新增用户设置。
